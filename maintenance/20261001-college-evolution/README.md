## 执行与证据

`inventory.sql`仅查询公共档案、原维护署名及RPC签名。`before.json`和`after.json`保存本批涉及的公共档案快照，不包含认证凭据。快照、结果JSON及携带具体数据的生成SQL只保留在本地，已由本目录`.gitignore`排除，不提交生产数据转储。数据库访问复用工作区既有的凭据管理器维护脚本；密钥未写入文件或日志。

`prepare.py`生成`changes.json`、`dry-run.sql`、`apply.sql`和`verify.sql`。每个既有档案按内容快照与预期版本核对，通过现有`apply_wiki_revision`写入；新院系通过`create_wiki_entity_with_body`建立。所有操作在一个事务内，验证失败即中止。RPC负责行锁和版本控制，不提升authenticated角色的表权限。署名沿用此前维护Creator test，修改说明明确记录本次院系纠正。

初次试运行遇到普通角色无法直接执行SELECT FOR UPDATE，改为使用RPC已有的锁；随后发现JSON传输将时间戳转为本地偏移，改按时间点比较时间戳，其他字段仍精确比较。一次SQL括号优先级错误也在回滚试运行阶段修正。上述失败事务未保留更改，没有修改权限。

最终回滚试运行28/28正文、关联、版本及修订快照通过，之后使用相同内容提交，提交结果再次28/28通过。`dry-run-result.json`、`apply-result.json`保存结果。`public-verification.json`记录13个公开目录、详情与历史页的HTTP 200及预期文字核对。

本次未重新部署线上应用；动态档案读取直接显示已保存内容。没有新增数据库迁移或修改数据库结构。未改写历史wiki修订、原始世界观附件和旧一次性导入记录。本地仓库检查单独记录在工程验证文档中。
