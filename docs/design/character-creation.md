# 角色创建：从问答到学生档案

## 范围与澄清

Campus首页增加角色创建入口，进入独立/create/character页面；这是可重复使用的创作工具，不限制为“第一个角色”。按学院→照片→能力→记忆点→名字五题，每题独立屏幕；五题均可跳过、返回补充，姓名留空为“未命名同学”，学院不关联、能力/记忆点留白。先弹出学生证，确认后才建立公开Student/Wiki档案及首个修订。访客可体验/下载，建立档案需要登录，浏览器保留输入。

## frontend-design简报

对象为空天大学的虚构角色入学档案；面向创作者，单一任务是将灵感变成角色档案。沿用学院官网：纸白#FBFDFF、天空#E8F3F8、深海#123B5A、钢蓝#4F6A80、边线#CBD7E6、印章金#946923。标题宋体，正文Microsoft YaHei/Inter，步骤与学生号Consolas。主布局为问答舞台+逐渐填满的学生证，移动端上下排列；每个问题独立一屏，避免传统长表单。标志元素是一张随回答逐步“入档”的学生证，最终以轻微翻转/落印弹出。题间为短暂横向纸页扫过；能力以缓慢轮播的真实人物片段帮助理解，可暂停和点选查看，减少动效时静止。

自我批评：不做通用SaaS步骤表、积分奖励或随机稀有度；游戏感来自角色与入学留影，不虚构能力等级/学院规则。首页入口明确“创建角色”，引导文案不限定首次访问。使用已有原画部件与证件底图，不另造占位美术。

## 契约

复用campus-card-activity/campus-card现有捏脸代码与素材的本站副本，独立同源iframe仅提供形象编辑；禁用原打印接口，不改动原站或源工作树。严格校验postMessage来源/窗口，只交换渲染照片与部件状态。上传、捏脸和默认形象均生成同样的证件照，最终通过已有媒体上传接口持久化。新student_character_cards关系表保存人物/证件媒体/外观与幂等请求UUID；创建RPC调用现有Wiki修订路径，原子建立Student和首个修订，不绕过Wiki权限/历史。学生证与照片媒体校验当前作者所有权、ready状态、媒体文件格式与大小；其他人的私有媒体不能附加。创建重试不重复产生档案。既有人物不要求补卡。

## 验收计划

首页入口、五题任意跳过/回退、全跳过仍可产出、默认/捏脸/上传照片、能力轮播暂停与减少动效、弹窗焦点与Escape、手机布局、登录前后恢复、下载、失败重试和幂等、防跨账号媒体使用、Wiki首个修订/公开图片/旧档案兼容。静态/数据库/浏览器与生产证据分别记录。

## 2026-10-17 补充

所有弹窗在视口水平、垂直居中（固定定位、inset:0、margin:auto，超高内容在弹窗内滚动）。最终校园卡仅写入姓名和学号，不添加学院名称；学院选择只进入角色档案及创建过程的档案预览。
