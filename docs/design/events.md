# 校史事件 / M5

面向查阅校史的访客，页面的单一任务是按时间和关联人物、学院、地点找到事件，并阅读其经过与独立资料。公开文案采用大学档案馆口吻，不强调虚构或共创机制；真实维护者的署名保留在档案资料区。

视觉：档案白 #fbfbf8、浅灰蓝 #edf2f6、海军蓝 #0a2147、夜蓝 #07182f、航空蓝 #296cb7。标题沿用宋体，正文使用无衬线，日期采用等宽字体。索引采用年份边栏和横向条目，详情采用深蓝卷首、浅色正文和按真实顺序连接的时间线。标志元素是时间节点与独立补充材料的对应关系；无意义编号、统计卡片和示例事件不进入正式页面。

反模板检查：事件不是论坛行的复制或统一卡片瀑布；时间线承担顺序信息，颜色不代替语义。移动端时间线缩成单轴；表单按钮触控高度至少44px，键盘有可见焦点，无必须依赖动画或悬停的操作。

契约：events 由唯一 creator_id 维护，event_timeline_nodes 保持 stable UUID，event_entity_links 使用 student_id/college_id/place_id 明确外键列存储实体 UUID。其他作者经 event_supplements 提交独立署名的补全细节、人物视角、后续影响、传闻·未证实、不同观点（兼容专题文章、亲历记述、文献资料），可关联某一节点。传闻性质在独立资料页与时间节点来源中持续显示。草稿、预览、发布与更新均调用版本检查 RPC；公开查询仅发布内容，补充还显式检查父事件为 published，避免登录作者的私有读取权限影响公开入口。日期范围使用 starts_on/ends_on，time_range 负责自然语言呈现并为发布必填。summary≤2000，causes/consequences≤10000，与数据库约束一致。

已实现 `/events` 的关键词、人物、学院、地点、日期交集检索，独立事件与补充阅读页；`/create/event` 的个人档案列表、主档案编辑、节点排序、实体选择、独立补充、私有完整预览。公开事件与补充接入 WorkCommunity，私有预览不接入。正式空态不注入示例事件。`getEvent()` 返回规范化 links 供组件使用。

React 19 表单注意事项：客户端先捕获 FormData，再在 startTransition 中调用 action，避免 action 返回验证/冲突错误时自动清空未受控表单。发布意图通过 hidden intent 明确携带，避免 pending 禁用按钮丢失 submitter。保存后编辑器用 id:version key 恢复对应已保存版本。
