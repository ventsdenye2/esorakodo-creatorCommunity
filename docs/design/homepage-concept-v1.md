# 首页前端设计方案 v1

> 状态：**当前已实现的功能型基线**。后续改版指导见 `living-campus-v2.md`（拟实施）；v2 的 Campus Layer、轻量空间预览、Relation Field 与 Entity Peek 尚未在本页实现。以下设计与验收记录保留为 v1 历史证据。

## 页面命题

- 对象：作为“空天大学本身”存在的数字校园首页。
- 受众：第一次进入世界的读者，以及准备创建人物和作品的 Creator。
- 单一任务：让用户理解这是一个由人物、地点、作品和事件相互连接的校园，并选择进入创作或探索路径。

- 标题：中文宋体系统栈，形成大学档案与出版物气质。
- 正文与控件：中文无衬线系统栈，确保小字号和表单可读。
- 档案编号：等宽字体，仅用于时间、类型和记录编号。
- 形状：以开放版式、表格、轨迹和横向档案带为主，不采用默认卡片网格。

## 记忆点

`Campus Trace` 是唯一重点动态元素。它通过事件、人物、机构和论坛身份四组可访问标签页，把林若岚、玄学院、北校区大停电和 @北楼观察者组织成可切换的档案关系。视觉由代码原生的轨道、节点和连接标签组成，不再假设尚未完成的校园建筑设计。

## 自我批评

- 白底、宋体、细线容易变成通用报纸模板。修正方式：所有线条、编号和分区都承载实体关系、楼层、时间线或档案来源，不添加装饰性栏目。
- 空天主题容易变成蓝黑霓虹 HUD。修正方式：空间感来自尺度和轨迹，主页面保持明亮；深蓝只用于事件档案这一处强节奏带。
- 动效容易成为与内容无关的装饰。修正方式：只让当前档案面板、关系轨道和节点响应标签切换，其他区域保持安静；所有实体名称、描述、按钮和焦点均由 HTML 提供。
- 未定稿的校园建筑会过早锁定世界观。修正方式：首页不展示任何具体建筑形象，直到建筑设定经过独立设计和确认。
- 视觉可能压过当前功能阶段。修正方式：首页只连接现有路由；不添加搜索、假数据指标或尚未存在的复杂交互。

## 验收视口

- 桌面：1440 × 900，检查首屏平衡和下一区域预告。
- 小屏：375 × 812，检查导航、标题换行、标签页重排、轨道缩放、时间线和横向溢出。
- 辅助检查：标签页左右方向键与 Home/End、键盘焦点、跳转链接、对比度、44px 触控区域和 reduced motion。

## 本轮验收记录

- 桌面 1440 × 900：首屏、完整长页与标题换行通过视觉检查。
- 移动端 375 × 812：单列降级、导航、事件时间线与页脚通过视觉检查，无横向溢出。
- 交互：从首页“进入论坛”成功到达 `/forum`，浏览器返回后首页状态正常。
- 无障碍：保留跳到主要内容链接、语义化标题层级、可见焦点和 reduced-motion 降级。
- 浏览器：全新 Playwright 会话未发现 console error 或 warning。
- 说明：本版是可替换的功能型视觉基线；后续美术调整不应改变语义结构、路由和数据边界。
