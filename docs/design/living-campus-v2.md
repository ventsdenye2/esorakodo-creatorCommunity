# Living Campus v2 前端设计指导

> 状态：**拟实施设计**（2026-09-23）。当前已运行的首页仍是 `homepage-concept-v1.md`；本文是后续前端改版的指导，不代表组件、3D 场景或真实关系数据已经交付。

## 命题与边界

空天大学官网是学校对外的门户；共创平台要让访客像走进一所正在生长的大学，沿人物、档案、论坛讨论和地点继续探索。界面围绕四个问题组织：**Entity**（有什么）、**Relation / Trace**（如何连接）、**Space / Campus**（发生在哪里）、**Time**（何时发生）。Forum、Press、Events、Wiki 是阅读这些信息的不同媒介，各有信息结构。

这里的 Entity 是前端交互概念，**不新增通用 Entity 数据表**。Student、College、Place、Event、Forum Account、作品继续使用各自领域模型和稳定 ID。3D 物体只是视图，不承载作品所有权、叙事事实或数据库业务逻辑。

本设计遵守已选定的公开测试版范围：账户、Wiki、论坛为首发业务；校刊、事件、真实 3D 模型可保留清楚的入口和可读占位，未完成的业务不能展示为可操作功能。视觉改版按阶段验证，不能取代 M1–M3 的 Auth、RLS、发布权限和浏览器验收。

## 视觉语言

方向为 **Institutional × Editorial × Spatial × Living Archive**：以大学、出版、档案与建筑沙盘为主体，航空航天元素用于精确的空间感。保留白 / 档案灰 / 深海军蓝 / 航空蓝 / 少量信号橙；避免通用 SaaS 仪表盘、卡片瀑布流、满屏霓虹 HUD、玻璃拟态和无意义粒子。深色大区块主要用于校史事件，表达进入历史的叙事状态。

以下是 v2 **候选令牌**，实施时应先与现有 CSS 对照，再通过变量迭代；不是本批已验证的视觉成品：

| 角色 | 候选值 | 用法 |
| --- | --- | --- |
| `--paper` / `--paper-soft` | `#fbfbf8` / `#f2f4f6` | 日常校园和次级操作区 |
| `--ink` / `--ink-soft` | `#0a2147` / `#56657a` | 正文与次级信息 |
| `--rule` / `--rule-soft` | `#cbd6e2` / `#e7edf2` | 真正的信息分隔 |
| `--sky` / `--sky-dark` | `#296cb7` / `#1d5799` | 链接、焦点与行动 |
| `--signal` | `#c7662e` | 有语义的提醒或事件信号 |
| `--night` / `--night-soft` | `#07182f` / `#102847` | 校史事件的夜间叙事区 |

宋体用于世界观标题、校刊和 Wiki 档案；无衬线用于导航、表单和正文操作；等宽字体仅用于档案编号、时间和坐标。线、编号、轨迹必须对应真实顺序或关系，不能只是装饰。

## 页面与交互契约

### 全局导航与首页

- 保持 `校园 / 论坛 / 校刊·部刊 / 校史事件 / 校园档案` 的路由结构。页头拟收紧至 76–80px；滚动后的约 64px 紧凑状态属于后续实现任务。真实“登录 / Creator”入口继续可用。
- 新增 **“◉ 校园视界”** 按钮打开 Campus Layer，而不是跳转到假页面。不存在的创作路由不得被放进导航；今后可用“＋创作”汇总已交付入口。
- Hero 保留“这所大学，仍在被共同书写。”和 `/wiki`、`/register` 两个真实入口。桌面布局以文案约 44% / 校园预览约 56% 为起点，不把空间场景变成整页背景。
- Hero 右侧拟放轻量 `CampusScenePreview`；当前 `CampusTrace` 下移并演进为关系探索区 `RelationField`。首屏空间、下方关系、论坛、校刊、事件各有各的版式，不重复一组卡片。
- “校园正在运行”的动态只能来自已发布的真实内容。没有真实来源时明确标成概念演示或使用诚实空状态，不伪造实时发帖和统计。

### Campus Layer 与未来 3D

- “校园视界”是整站唯一重点转场。桌面以 360–480ms 的克制 reveal 为设计目标；不支持或开启 `prefers-reduced-motion` 时用即时切换或短 fade。打开后焦点进入 Layer，Esc 可关闭，关闭后焦点回到触发按钮。
- 第一版使用 SVG / CSS 轻量沙盘预览，**不安装 Three.js**。校园列表、地点 Peek 和档案链接始终是可访问的 2D 路径；鼠标、触屏、键盘均可完成探索。
- 移动端首页只放轻量 Campus Poster；用户打开 Layer 后再呈现场景，上半屏为空间视图，下半屏为可操作的地点信息 sheet。触控目标至少约 44px，场景不是唯一导航。
- 重要场景节点最多 3–5 个。没有已经确认的 Place 与空间设定时，使用明确标注的概念点位，不把建筑示例、位置或坐标写成 Canon。
- 为将来的 GLB 预留独立 `CampusSpatialBinding`：稳定 Place ID/slug ↔ 3D objectName、锚点和相机预设。模型物体命名应稳定且可选取；模型替换不改数据库身份、Wiki URL 或作品引用。未来再接 Three.js / React Three Fiber，并在打开 Layer 后动态加载，首页首屏不打包完整 3D 引擎。
- 未来 GLB 压缩体积 6–8 MB、DPR 1–1.5 和按需渲染只是**规划预算**，要在真实模型到位后测量并调整。

### Entity Peek 与 Trace

- `EntityLink` 的基础仍是可直接访问的 `<a href>`。Peek 只是渐进增强：指针悬停约 180ms 或键盘聚焦可显示档案签；触屏操作要有明确的“打开档案”路径。Esc 关闭，移出延迟约 150ms，避免闪烁。
- Peek 用纸面、细档案线、编号与少量阴影，不用玻璃卡。摘要、关系和来源必须取自实际可读数据；缺少关系时保留普通链接。
- `RelationField` 的连线只绘制已知关系。用户浏览路径可以形成轻量 Trace，但要区分“当前会话走过的页面”与数据库中已确认的实体关系，不凭视觉推断新事实。

### 媒介差异

| 媒介 | 阅读形态 | 必须保留的边界 |
| --- | --- | --- |
| Forum | BBS / 校园信息栏的行式列表；详情按真实楼层顺序阅读 | 戏内 Forum Account 楼层与现实 Creator 的操作/戏外讨论分开；行 hover 可轻移，避免卡片浮起 |
| Press | 校刊出版物的标题、编号、留白与长文节奏 | 不复用论坛行或统一内容卡片 |
| Events | 档案与时间线；夜间深蓝区只在重大校史叙事中使用 | 顺序、时间和来源有意义，未实现的事件不能伪装为实时内容 |
| Wiki | 可追溯档案、Revision 和稳定关系入口 | 共创编辑与作品使用分离，改动仍通过事务生成 Revision |

## 实施阶段与文件围栏

每阶段先完成设计简报、实现和实际 QA，再进入下一阶段；后端业务继续按 M1–M3 的依赖推进。前端纯视图工作可与论坛数据库工作并行，但共享类型、数据契约和入口需要集成检查。

1. **Visual Foundation**：更新令牌与页头，保留现有路由和语义。预计修改 `app/globals.css`、`src/components/layout/`。
2. **New Hero**：抽出 `CampusHero`，以轻量 `CampusScenePreview` 替换 Hero 右侧轨道。预计修改 `app/page.tsx`、`src/components/home/`、新 `src/features/campus/`。
3. **Campus Layer**：完成触发、打开/关闭、焦点、Esc、移动端 sheet、地点列表/Peek 和 reduced motion。空间预览只用已确认或明确标注的演示数据。
4. **Relation Field**：将当前 `CampusTrace` 演进为真实关系导航；静态演示数据必须保持演示标识。
5. **Entity Peek**：增强 `src/components/entity-link/`，保留普通链接和 SSR 可达性。
6. **Editorial Restyle**：分别调整 `CampusActivity`、`EditorialFeed`、`EventArchive`、`WikiTrail`，不将三种媒介统一卡片化。
7. **QA 与收敛**：在有数据和空数据下检查桌面 `1440×900`、`1280×800`，移动 `390×844`、`375×812`；检查键盘、焦点返回、触屏、reduced motion、对比度、无横向溢出、SSR、lint、typecheck、build 和相关测试。

本设计阶段不得借机修改 Supabase schema、RLS、Auth、Wiki Revision 事务和领域所有权。后续若 3D 地图需求确实需要新的空间元数据，先在 RDS 中提出独立契约与迁移验收，再写数据库代码。

## 来源与状态核对

本规范据用户提供的《设计共创平台前端》讨论整理，并与当前仓库 `AGENTS.md`、`homepage-concept-v1.md`、`app/page.tsx` 和现有组件对照。讨论中的示意坐标、建筑、时间、事件与性能数字是设计示例或目标，均非当前真实数据、已测性能或已批准 Canon。
