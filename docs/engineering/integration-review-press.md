# Press 与作者/社区集成复核 — 2026-09-23

## 修复
- 作者自己的公开主页曾可能列出父事件不可见的已发布补充：RLS允许作者读取自己的作品，因此公开展示不能仅依赖RLS。`creatorWorks` 现在批量查验父事件明确为published，公开页过滤其余补充，工作区把父事件不可见的补充标为暂不可见。
- 收藏由逐项查询（最多100次）改为按媒介最多四次批量查询及一次父事件检查。每个媒介强制published，补充还要求父事件published；查询失败会返回failed而不假装收藏为空。
- Creator 工作区隐藏作品不再提供注定无效的公开阅读链接；已发布校刊、事件与补充提供编辑入口，论坛保持发布冻结。
- 赞/收藏计数或当前状态查询失败时显示错误，不再默认为0赞或未收藏；缺失作者资料不会生成空用户名链接。
- 社区评论、举报改为受控正文并在成功后清空、失败保留；所有操作先捕获包括提交按钮的FormData再进入pending，避免禁用submitter导致action丢失。发布动作本身未由该审查执行。

## 复核结论
- 作者公开主页调用 `creatorWorks(id)`，对各媒介明确过滤published。浏览器以持有自己草稿的已登录作者打开公开主页，显示“暂无公开作品”，未泄露草稿。
- 校园首页所有作品查询明确published；事件补充使用inner parent join与父事件published过滤；首页读取使用请求级React cache。未修改主线首页。
- 检索只读取公开展示字段，作品明确published；关键词转义LIKE通配符、长度受限，并按媒介限量。未修改主线检索。
- 公开作者页仅读取id/handle/display_name/bio，没有邮件或Auth凭据。
- 数据库社区只允许公开作品互动、删除评论以deleted过滤，应用不绕开事务权限。

## 证据与限制
`npm run typecheck` 与本批涉及的ESLint验证交主线最终统一复跑；Press模块此前已独立通过。草稿、并发冲突、手机和公开主页浏览器证据见 `docs/design/press.md`。没有为集成审查创建新发布状态。浏览器发布测试被自动审核拒绝，未绕过；最终完整发布验收仍需单独明确授权或用户手动完成。
